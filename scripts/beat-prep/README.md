# Beat prep pipeline

`prep-beats.sh` turns a folder of finished beats into protected web previews:

    ./prep-beats.sh ~/Desktop/beats ~/tags/thebeatmob-dry.wav ./previews

What it does per beat:
- trims to 60s (change with `PREVIEW_LEN`)
- mastering pass: high-pass 28Hz, low-end + air EQ, glue compression (2.5:1),
  EBU R128 loudness to -14 LUFS (streaming standard), safety limiter at -1.2dB
- 4 producer tags, mixed in (not slapped on): clean drop at the intro, wet tag
  at the verse start, a telephone-FX tag mid-verse, a wide tag on the chorus.
  The beat ducks under every tag like a radio drop.
- encodes 128kbps mp3 previews (small enough to ship in the repo, tagged enough
  that a stolen file still says your name)

Placement is `TAG_TIMES="0,16,32,45"` by default — tune per arrangement, or
per-beat: run the script once with different TAG_TIMES for a specific file.

The tag file: one dry spoken drop, e.g. "TheBeatMob". All FX are generated by
the script, so record one take and let the pipeline do the rest.

`beats-manifest.json` comes out ready to paste into `src/data/beats.ts` — each
entry's `audioUrl` makes the site player use the real file instead of the
in-browser placeholder synth.

## Why baked-in tags
Player-side tags can be stripped by grabbing the raw audio URL; tags baked
into the preview file mean any copy that escapes the store still credits
Prod.TheBeatMob. Masters (untagged) never touch the browser — buyers get files
delivered by the plug.
